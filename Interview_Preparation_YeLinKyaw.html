🛡 1. CSV Formula Injection (CWE-1236) Mitigation — CsvExportUtil.java
ဘာကို စစ်ထားတာလဲ? အသုံးပြုသူများ နာမည် သို့မဟုတ် ငွေလွှဲမှတ်ချက်ထဲတွင် Excel Formula အစပြုသင်္ကေတများ (=, +, -, @, , ) ရိုက်ထည့်ထားပါက Excel ဖွင့်ကြည့်သည့်အခါ Malicious Code အဖြစ် အလိုအလျောက် Run သွားနိုင်သည့် အန္တရာယ် (Formula Injection) ကို ကာကွယ်ထားသည်။
// CsvExportUtil.java — CWE-1236 Prevention if (s.startsWith("=") || s.startsWith("+") || s.startsWith("@") || s.startsWith(" ") || s.startsWith(" ")) { s = "'" + s; // Apostrophe ဖြင့် ရှေ့မှ prefix ထည့်၍ text အဖြစ် ပြောင်းလဲ } else if (s.startsWith("-") && !isNumeric(s)) { s = "'" + s; } // RFC-4180 standard quotation & double quotes escaping if (s.contains(",") || s.contains(""") || s.contains(" ") || s.contains(" ")) { return """ + s.replace(""", """") + """; }

"Excel ဒါမှမဟုတ် CSV export အကြီးကြီးတွေ ထုတ်တဲ့အခါ Server Memory Out Of Memory (OOM) မဖြစ်အောင် ဘယ်လို ကာကွယ်ခဲ့လဲ?"

Key Talking Points (အဓိက အချက်များ)

စံနမူနာ အဖြေ:
"Standard Apache POI ရဲ့ XSSFWorkbook ဟာ Excel ရဲ့ XML tree တစ်ခုလုံးကို Java Heap Memory ပေါ်မှာ တည်ဆောက်တဲ့အတွက် Record ပေါင်း ၅ သောင်း သို့မဟုတ် ၁ သိန်းကျော်ပါက Heap Space ကုန်ပြီး java.lang.OutOfMemoryError: Java heap space ဖြစ်စေပါတယ်။
ကျနော် ဒါကို ကာကွယ်ဖို့အတွက် SXSSFWorkbook (Streaming POI) ကို သုံးခဲ့ပါတယ်။ Memory ပေါ်တွင် Row ပေါင်း ၁၀၀ သာ ထိန်းသိမ်းထားပြီး Row ၁၀၀ ကျော်လွန်သွားသော Record အဟောင်းများကို Hard Disk ပေါ်ရှိ Temporary File သို့ အလိုအလျောက် Flush လုပ်စေပါတယ်။ ဒါကြောင့် Record ပမာဏ မည်မျှပင် ကြီးမားစေကာမူ Server Heap Memory ကို MB အနည်းငယ်သာ အသုံးပြုစေပြီး Server Crash မဖြစ်အောင် အပြည့်အဝ ကာကွယ်ပေးထားပါတယ်ခင်ဗျာ။"

"လုံခြုံရေးပိုင်းမှာ အဓိက အချက် ၅ ချက်ကို စနစ်တကျ စစ်ဆေးထားပါတယ်:
၁) CSV Formula Injection (CWE-1236): Data များထဲတွင် Excel Formula စတင်သင်္ကေတများ (=, +, -, @) ပါလာပါက Apostrophe (') ဖြင့် Prefix ထည့်ပြီး Plain text အဖြစ် ပြောင်းလဲထားပါတယ်။
၂) Path Traversal Prevention: Async Export ဖိုင်နာမည်များတွင် User Input ကြောင့် Directory Traversal မဖြစ်စေရန် Regex (replaceAll("[:\\/*?"<>|]", "_")) ဖြင့် သန့်စင်ထားပါတယ်။
၃) Role-Based Access Control: အရေးကြီး အစီရင်ခံစာများကို ADMIN နှင့် AUDITOR သာ ကြည့်ရှုခွင့်ရစေရန် Spring Security @PreAuthorize ဖြင့် ကာကွယ်ထားပါတယ်။
၄) Data Privacy & PII Masking: ဘဏ်ဖောက်သည်များ၏ Account No ကို ******6543 ပုံစံ၊ NRC နှင့် ဖုန်းနံပါတ်များကို Mask လုပ်ပေးသည့် DataMaskingUtil ကို အသုံးပြုထားပါတယ်။
၅) Customer Ownership Check: Customer Portal တွင် အခြားသူ၏ Account သို့ တောင်းဆို၍ မရစေရန် JWT Token ထဲမှ customerId နှင့် Account ပိုင်ရှင်ကို တိုက်ဆိုင်စစ်ဆေးထားပါတယ်ခင်ဗျာ။"
