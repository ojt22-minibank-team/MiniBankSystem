sp_get_daily_ledger_summary — နေ့စဉ် Debit/Credit Ledger အချုပ် တွက်ချက်ခြင်း

ရည်ရွယ်ချက်နှင့် အလုပ်လုပ်ပုံ:
ရက်စွဲအပိုင်းအခြား (p_start_date မှ p_end_date) အတွင်း ဖြစ်ပွားခဲ့သော Transaction များကို ရက်စွဲအလိုက်၊ Transaction Type အလိုက်၊ ငွေကြေးအမျိုးအစား (Currency) အလိုက် Group ဖွဲ့ပြီး စုစုပေါင်း အရေအတွက် (COUNT)၊ စုစုပေါင်း ပမာဏ (SUM(amount)) နှင့် ဝန်ဆောင်ခ (SUM(service_fee)) များကို တစ်ပြိုင်နက်တည်း တွက်ထုတ်ပေးသည်။
CREATE PROCEDURE sp_get_daily_ledger_summary( IN p_start_date DATE, IN p_end_date DATE, IN p_status VARCHAR(25) ) BEGIN SELECT DATE(bt.completed_at) AS report_date, bt.transaction_type AS transaction_type, COUNT(bt.transaction_id) AS transaction_count, COALESCE(SUM(bt.amount), 0.0000) AS total_amount, COALESCE(SUM(bt.service_fee), 0.0000) AS total_fee, bt.currency AS currency FROM bank_transactions bt WHERE bt.completed_at >= CAST(CONCAT(p_start_date, ' 00:00:00') AS DATETIME) AND bt.completed_at <= CAST(CONCAT(p_end_date, ' 23:59:59') AS DATETIME) AND (p_status IS NULL OR p_status = '' OR bt.status = p_status) GROUP BY DATE(bt.completed_at), bt.transaction_type, bt.currency ORDER BY report_date DESC, total_amount DESC; END //
💡 Performance Optimization Note:
idx_bt_reporting_perf Covering Index ရှိသည့်အတွက် Table Full Scan မလုပ်ဘဲ Index Range Scan ဖြင့် မီလီစက္ကန့်ပိုင်းအတွင်း သန်းချီသော ဒေတာမှ ချက်ချင်း တွက်ထုတ်ပေးနိုင်သည်။

sp_get_customer_account_status_summary — Multi-Result Sets (အကောင့်အခြေအနေနှင့် Balance Brackets)

ရည်ရွယ်ချက်နှင့် အလုပ်လုပ်ပုံ:
အကောင့်များ၏ အခြေအနေ (Active, Inactive, Suspended, Frozen) အလိုက် စာရင်းအင်းများနှင့် ငွေပမာဏအပိုင်းအခြား (Balance Brackets: 0-100K, 100K-1M, 1M-10M, 10M+) များကို Result Set ၂ ခု ပြိုင်တူ ထုတ်ပေးသည်။
CREATE PROCEDURE sp_get_customer_account_status_summary( IN p_start_date DATE, IN p_end_date DATE, IN p_account_status VARCHAR(20) ) BEGIN -- Result Set 1: Account Status Distribution (Avg, Min, Max, New Accounts) SELECT a.status AS account_status, COUNT(a.account_id) AS account_count, SUM(CASE WHEN a.created_at >= CAST(CONCAT(p_start_date, ' 00:00:00') AS DATETIME) AND a.created_at <= CAST(CONCAT(p_end_date, ' 23:59:59') AS DATETIME) THEN 1 ELSE 0 END) AS new_accounts_in_range, COALESCE(AVG(a.current_balance), 0.0000) AS avg_balance, COALESCE(MIN(a.current_balance), 0.0000) AS min_balance, COALESCE(MAX(a.current_balance), 0.0000) AS max_balance FROM accounts a WHERE (p_account_status IS NULL OR p_account_status = '' OR a.status = p_account_status) GROUP BY a.status; -- Result Set 2: Balance Bracket Distribution via CASE WHEN SELECT CASE WHEN a.current_balance < 100000 THEN '0 - 100K' WHEN a.current_balance < 1000000 THEN '100K - 1M' WHEN a.current_balance < 10000000 THEN '1M - 10M' ELSE '10M+' END AS balance_bracket, a.status AS account_status, COUNT(a.account_id) AS bracket_count, COALESCE(SUM(a.current_balance), 0.0000) AS bracket_total_balance FROM accounts a WHERE (p_account_status IS NULL OR p_account_status = '' OR a.status = p_account_status) GROUP BY balance_bracket, a.status ORDER BY MIN(a.current_balance) ASC; END //

sp_large_transaction_aml_report_paged — AML စောင့်ကြည့်ရေး စနစ်သစ်

အင်ဂျင်နီယာဆိုင်ရာ ဗိသုကာထူးခြားချက် (Architectural Highlight):
Pagination ပြုလုပ်ရာတွင် COUNT(*) OVER() သို့မဟုတ် Subquery သုံးပါက Table ကြီး ၄ ခု (bank_transactions, accounts, customers) ကို Join ပြီးမှ Count လုပ်သဖြင့် အလွန် ကြန့်ကြာစေသည်။
ကျနော်သည် Result Set ၂ ခု ခွဲထုတ်သည့် နည်းပညာ ကို တီထွင်ခဲ့သည်:
• RS1 (Summary Scanning): Join မပါဘဲ Covering Index သာ သုံး၍ စုစုပေါင်း Flagged Count, စုစုပေါင်း ပမာဏ, High Risk Count (>= 2x threshold), Medium Risk Count များကို 0.03 စက္ကန့်အတွင်း တွက်ထုတ်သည်။
• RS2 (Paginated Rows): အသုံးပြုသူ ကြည့်လိုသော ၃၀ Row ကိုသာ Accounts/Customers ဇယားများနှင့် Left Join တွဲ၍ အမည်နှင့် အကောင့်နံပါတ်များ ထုတ်ပေးသည်။

@Repository public class ReportRepository { private final JdbcTemplate jdbcTemplate; public AccountStatusReportDTO getAccountStatusSummary( LocalDate startDate, LocalDate endDate, String accountStatus) { return jdbcTemplate.execute((Connection con) -> { // 1. Stored Procedure ခေါ်ယူရန် CallableStatement ပြင်ဆင်ခြင်း CallableStatement cs = con.prepareCall("{CALL sp_get_customer_account_status_summary(?, ?, ?)}"); cs.setObject(1, startDate); cs.setObject(2, endDate); cs.setString(3, (accountStatus == null || accountStatus.isBlank()) ? null : accountStatus); return cs; }, (CallableStatement cs) -> { List<AccountStatusSummaryDTO> statuses = new ArrayList<>(); List<BalanceBracketDTO> brackets = new ArrayList<>(); // 2. Execution စတင်ပြီး ပထမ Result Set (RS1) ဖတ်ယူခြင်း boolean hasRs = cs.execute(); if (hasRs) { try (ResultSet rs = cs.getResultSet()) { while (rs.next()) { statuses.add(AccountStatusSummaryDTO.builder() .accountStatus(rs.getString("account_status")) .accountCount(rs.getLong("account_count")) .newAccountsInRange(rs.getLong("new_accounts_in_range")) .avgBalance(rs.getBigDecimal("avg_balance")) .minBalance(rs.getBigDecimal("min_balance")) .maxBalance(rs.getBigDecimal("max_balance")) .build()); } } // 3. ဒုတိယ Result Set (RS2) ရှိမရှိ စစ်ဆေးပြီး ရွှေ့ပြောင်းခြင်း hasRs = cs.getMoreResults(); } // 4. ဒုတိယ Result Set (RS2: Balance Brackets) ဖတ်ယူခြင်း if (hasRs) { try (ResultSet rs = cs.getResultSet()) { while (rs.next()) { brackets.add(BalanceBracketDTO.builder() .balanceBracket(rs.getString("balance_bracket")) .bracketCount(rs.getLong("bracket_count")) .bracketTotalBalance(rs.getBigDecimal("bracket_total_balance")) .accountStatus(rs.getString("account_status")) .build()); } } } // 5. Result Set ၂ ခုလုံးကို DTO တစ်ခုတည်းအဖြစ် ပေါင်းစပ်၍ Return ပေးခြင်း return AccountStatusReportDTO.builder() .statusSummaries(statuses) .bracketDistribution(brackets) .build(); }); } }

Producer-Consumer Asynchronous Job Architecture

အသုံးပြုသူသည် Report အကြီးကြီးများကို Export ထုတ်ရန် နှိပ်လိုက်သည့်အခါ စနစ်အတွင်း အောက်ပါအတိုင်း အသစ်ဖန်တီးခြင်း (Job Creation) နှင့် နောက်ကွယ်မှ ဆောင်ရွက်ခြင်း (Async Worker) တို့ အလုပ်လုပ်ပါသည်:

STEP-BY-STEP

Background Export Job Creation & Download Lifecycle

အဆင့် (၁) Submit:
Client မှ POST /api/v1/reports/export-async?reportType=...&format=xlsx သို့ တောင်းဆိုမှု ရောက်ရှိလာသည်။ ReportExportJobService.submitExportJob() က UUID ဖြင့် Job ID အသစ် ဖန်တီးသည် (ဥပမာ exp_7a8b9c0d1e2f)။
အဆင့် (၂) Accepted:
Status ကို PENDING ဟု သတ်မှတ်ပြီး Thread-safe ဖြစ်သော ConcurrentHashMap<String, JobRecord> ထဲသို့ သိမ်းဆည်းသည်။ Web Thread ပိတ်ဆို့မှု မရှိစေရန် Client သို့ HTTP 202 (Accepted) ဖြင့် Job DTO ကို မီလီစက္ကန့် ၂၀၀ အတွင်း ချက်ချင်း ပြန်ပို့ပေးသည်။
အဆင့် (၃) Background:
Spring Thread Pool Executor တွင် executeAsyncJob() စတင် Run ပါသည်။ Job State သည် PROCESSING သို့ ကူးပြောင်းပြီး Stored Procedure မှ ဒေတာများကို ဖတ်ယူကာ JasperReports သို့မဟုတ် POI SXSSF ဖြင့် Binary Bytes များ ထုတ်လုပ်သည်။
အဆင့် (၄) Write to Disk:
ထုတ်လုပ်ပြီးသော File Bytes များကို Server RAM ပေါ်တွင် မထားဘဲ OS ၏ Temp Folder ထဲရှိ cb-report-exports/ Directory ထဲသို့ ရေးချသိမ်းဆည်းလိုက်သည်။ Job Status ကို COMPLETED သို့ ပြောင်းလဲပေးသည်။
အဆင့် (၅) Polling & DL:
React Custom Hook (useAsyncExport) က ၁.၅ စက္ကန့်ခြား GET /api/v1/reports/export-jobs/{jobId} ကို လှမ်းစစ်နေပြီး COMPLETED ဖြစ်သည်နှင့် /download endpoint မှတစ်ဆင့် File Blob ကို Browser သို့ အလိုအလျောက် Download ဆွဲပေးသည်။
